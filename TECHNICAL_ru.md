# 🛠️ Техническая документация (Minecraft Server Deployment)

Эта документация описывает архитектуру, процесс CI/CD, резервное копирование и скрипты сервера. Для информации об игровом процессе смотрите основной [README_ru.md](README_ru.md).

## 🛠️ Архитектура и CI/CD (Jenkins)

Деплой осуществляется автоматически через **Jenkins** по протоколу SSH. Jenkins копирует необходимые скрипты и конфигурации на целевой сервер и запускает/обновляет контейнеры через `docker-compose`.

### Опции деплоя (Jenkins)
По умолчанию запуск сборки Jenkins обновляет всю инфраструктуру целиком. Это включает в себя:
- Обновление основного сервера Minecraft (`mc`).
- Принудительную пересборку Docker-образа мониторинга `warden-monitor` (для обновления Python-зависимостей из `requirements.txt`) перед его перезапуском.

**Обновление мониторинга без даунтайма (Zero-Downtime):**
Если вам нужно обновить только контейнер `warden-monitor`, не перезагружая при этом сам сервер Minecraft (чтобы не отключать играющих игроков), вы можете поставить галочку `DEPLOY_MONITOR_ONLY` при запуске джобы в Jenkins ("Сборка с параметрами"). Этот режим скопирует только скрипты мониторинга и безопасно перезапустит исключительно его контейнер.

### Сборка и деплой кастомных плагинов (WardenLog)
В репозитории есть исходный код кастомного плагина `WardenLog` (папка `plugins-src`). 
Пайплайн Jenkins (`Jenkinsfile`) автоматически:
1. Собирает плагин с помощью Maven в Docker-контейнере.
2. Пропускает сборку, если версия не менялась.
3. Копирует готовый `.jar` файл в папку `/opt/minecraft/data/plugins/` на боевом сервере.
4. Перед запуском контейнеров Jenkins принудительно создает папку `WardenLog` и устанавливает правильные права доступа, чтобы избежать конфликтов с Docker-демоном (который по умолчанию создает директории от имени `root`).

## 💾 Сохранность данных

Все игровые данные хранятся на хост-сервере в директории деплоя:
`/opt/minecraft/data`

Это гарантирует, что данные (миры, плагины, настройки) полностью сохраняются:
- При жесткой перезагрузке сервера.
- При повторных деплоях новой конфигурации через Jenkins.

### Автоматические бэкапы
Сервер настроен на ежедневное создание резервных копий (в 2:00 ночи). Бэкапы сохраняются в папке `backups` в виде `.tar` архивов, при этом хранятся только последние 3 бэкапа для экономии места.

**Как восстановить сервер из бэкапа:**
1. Остановите сервер: `docker-compose stop mc`
2. Переименуйте текущую папку `data` в `data_old` и создайте новую пустую папку `data`.
3. Зайдите в папку `backups` и распакуйте нужный вам архив прямо в новую папку `data` (с помощью 7-Zip или стандартных средств ОС).
4. Снова запустите сервер: `docker-compose start mc`

## 🚀 Как запустить

Всё работает автоматически через пайплайн `minecraft` на вашем Jenkins. Любые изменения в `docker-compose.yml` (например, добавление новых плагинов в `MODRINTH_PROJECTS`) после коммита автоматически применятся на сервере.

### Автоматическая донастройка
В репозитории есть встроенный скрипт `scripts/auto-patch-authme.sh`. Он автоматически запускается внутри контейнера сервера и "на лету" правит конфиг AuthMe, как только тот генерируется:
1. Настраивает плагин так, чтобы пускать игроков с телефонов без пароля (интеграция Floodgate).
2. Разрешает символ точки `.` в никнеймах (нужно для Bedrock-игроков).
3. Увеличивает таймаут авторизации до 120 секунд.
4. Разрешает играть до 4 человек с одного IP-адреса (удобно, когда вся семья играет из дома через один Wi-Fi).
5. Автоматически устанавливает дневное время в игре (`/time set day`) при регистрации и при каждом входе игрока на сервер.

**Как использовать:**
Никак! Всё работает на 100% автоматически. Скрипт запускается в фоне при старте контейнера, сам ждет появления файла настроек, сам его изменяет и сам мгновенно перезагружает плагин. Вам больше не нужно заходить по SSH!

## 📊 Prometheus Метрики & Webhook (Warden)

Контейнер `warden-monitor` собирает и отдает метрики в формате Prometheus на порту `8000` (`http://<SERVER_IP>:8000/metrics`).

### Webhook API (Оповещения)
На порту `8002` (проброшен из `8001` внутри контейнера) работает скрытый API для отправки глобальных объявлений всем игрокам на сервере.
- **Endpoint:** `http://<SERVER_IP>:8002/alert?msg=Ваше_сообщение`
- **Результат:** Все игроки увидят на экране крупный красный текст "ВНИМАНИЕ" и подзаголовок с вашим сообщением.
Это полезно для автоматических скриптов или предупреждений перед рестартом сервера.

### Доступные метрики:

| Метрика | Тип | Описание | Метки (Labels) |
| --- | --- | --- | --- |
| `minecraft_server_online` | Gauge | Статус сервера (1 = работает, 0 = недоступен) | - |
| `minecraft_player_count` | Gauge | Количество игроков онлайн | - |
| `minecraft_server_ping_ms` | Gauge | Задержка (пинг) до сервера в миллисекундах | - |
| `warden_tnt_placed_total` | Counter | Общее количество установленных блоков динамита | `player`, `world`, `x`, `y`, `z`, `time` |
| `warden_tnt_exploded_total` | Counter | Общее количество взрывов динамита | `source`, `world`, `x`, `y`, `z`, `time` |
| `warden_player_joins_total` | Counter | Общее количество входов игроков на сервер | `player`, `time` |
| `warden_player_quits_total` | Counter | Общее количество выходов игроков с сервера | `player`, `time` |
